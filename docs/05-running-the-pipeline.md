# Running the pipeline

Everything needed to get `run_local.py` working from a clean checkout, plus the other two entry points and the environment variables the whole system reads.

## Prerequisites

### Python environment

```bash
pip install -r requirements.txt
```

This installs the **runtime** stack only: ONNX Runtime, numpy, opencv, faiss, scipy, Flask, Supabase client, psycopg2, python-dotenv. No `torch`, no `ultralytics`, no `torchreid`, no `scikit-learn`, no `mediapipe` — see [`requirements.txt` vs `requirements-export.txt`](#requirementstxt-vs-requirements-exporttxt) below for why, and [`08-legacy-and-dormant-code.md`](08-legacy-and-dormant-code.md) if you need `mediapipe` back for the dormant face/hand detectors.

### Model files — read this before assuming `.pt` files are enough

The production runtime loads **`.onnx` files**, not the `.pt` weights. `models/` is gitignored and nothing under it ships with the repo. To get a working setup:

1. Download the original `.pt`/`.onnx` weights from the Google Drive link in the repo root's `README.md`.
2. The runtime needs these files, generated by exporting the `.pt` weights (see [`07-testing-and-dev-tools.md`](07-testing-and-dev-tools.md) for `tools/export_to_onnx.py`):
   - `models/yolov10m.onnx` — person/object detector
   - `models/trained_yolo11m.onnx` — sit/stand pose classifier (needed because `DETECTOR_FLAGS["pose"]` is `True` by default)
   - `models/osnet_x1_0.onnx` — Re-ID embedder
3. These two are used as-is, no export needed, and are **only** required if you turn on the emotion/age flags (off by default — see [`08`](08-legacy-and-dormant-code.md)):
   - `models/emotion-ferplus-8.onnx`
   - `models/age_googlenet.onnx`

If a required `.onnx` file is missing, `runtime/loaders_onnx.py` raises `FileNotFoundError` with a message pointing at `tools/export_to_onnx.py --all`.

### `requirements.txt` vs `requirements-export.txt`

Two separate, non-overlapping environments:

| | `requirements.txt` | `requirements-export.txt` |
|---|---|---|
| Purpose | Running the pipeline (`run_local.py`, `run_webhook.py`, `run_live_capture.py`) | Regenerating `.onnx` files from `.pt` weights, via `tools/export_to_onnx.py` |
| Contains | `onnxruntime`, `numpy`, `opencv-python`, `faiss-cpu`, `scipy`, `flask`, `supabase`, `psycopg2`, `python-dotenv` | `torch`+`torchvision` (CUDA 11.8 build), `ultralytics`, `torchreid`, `onnx` |
| Install it for a normal pipeline run? | Yes, always | **No, never** — dev-only, offline export tooling |

The CUDA-pinned torch line lives entirely in `requirements-export.txt`, not `requirements.txt`. You only need it if you're re-exporting the ONNX files yourself; installing it via the CUDA 11.8 index (`pip install torch==2.7.1+cu118 torchvision==0.22.1+cu118 --index-url https://download.pytorch.org/whl/cu118`, then `pip install -r requirements-export.txt`) is a one-time setup for that specific task, not something `run_local.py` needs.

### Environment variables

All loaded via `python-dotenv`'s `load_dotenv()`, called independently in both files below (there's no centralized env-loading module, and no `.env.example` in the repo — this table is the closest thing to one).

| Variable | Loaded by | Required? | Default | Behavior if missing |
|---|---|---|---|---|
| `SUPABASE_URL` | `bootstrap.py` | For `run_webhook.py`/`run_live_capture.py` | — | Warns, continues with `supabase=None` |
| `SUPABASE_KEY` | `bootstrap.py` | Same | — | Same |
| `SUPABASE_BUCKET` | `bootstrap.py` | Same | — | Read alongside the above |
| `POSTGRES_HOST` | `postgres_writer.py` | Yes, for any run that persists results | — | `psycopg2.connect()` fails hard, no fallback |
| `POSTGRES_PORT` | `postgres_writer.py` | No | `5432` | — |
| `POSTGRES_DATABASE` | `postgres_writer.py` | Yes | — | Hard fail |
| `POSTGRES_USER` | `postgres_writer.py` | Yes | — | Hard fail |
| `POSTGRES_PASSWORD` | `postgres_writer.py` | Yes | — | Hard fail |
| `BATCH_SIZE` | `postgres_writer.py` | No | `1000` | Insert batch size tuning |
| `MAX_WORKERS` | `postgres_writer.py` | No | `2` | Thread-pool size for metadata/neighborhood inserts |
| `MAX_RETRIES` | `postgres_writer.py` | No | `3` | Deadlock-retry count |

`run_local.py` and `run_webhook.py` both call into `postgres_writer.py` at the end of every run, so the 5 `POSTGRES_*` required vars apply to both. `run_live_capture.py` doesn't touch Postgres at all.

## The three entry points

All paths resolve relative to the package location via `paths.py`, not the process's working directory — but you should still run these from the repo root as a matter of convention.

### `run_local.py`

```bash
python run_local.py
```

No arguments. Reads a hardcoded local sample folder (`keyFrames/` under the repo root, 5 keyframes), runs the pipeline once, writes to `res/`, and persists to Postgres. No Flask, no HTTP. This is the offline smoke-test path — the fastest way to confirm your setup works end-to-end.

Needs: the `.onnx` model files above, the 5 required `POSTGRES_*` vars. Supabase vars are optional (tolerated as missing).

### `run_webhook.py`

```bash
python run_webhook.py
```

A Flask app exposing `POST /webhook`. Expects a JSON body:

```json
{"record": {"folder_path": "...", "timestamp": "...", "speed_inference": 0.0}}
```

Downloads that folder from Supabase Storage into `mis_frames/`, runs the same pipeline as `run_local.py`, and additionally draws annotated debug images (`draw_debug=True`, unlike `run_local.py`'s default `False`). Returns `('No frames', 200)` if the download yields zero frames, `400` on a malformed request body.

**Import-time cost**: `init_runtime()` and the identity gallery are built at module import time (`R = init_runtime()` at the top level), not inside a request handler. Simply importing this module — e.g. under a WSGI server — pays the full model-loading cost immediately, before the first request arrives.

Needs: `SUPABASE_URL`/`SUPABASE_KEY`/`SUPABASE_BUCKET` (required here — it actively downloads), plus the 5 `POSTGRES_*` vars.

### `run_live_capture.py`

```bash
python run_live_capture.py
```

A thin wrapper (`asyncio.run(camerachatbot.capture.live_capture.main())`). Opens the local webcam (hardcoded camera index) via an async producer/consumer, chunks captured frames, extracts keyframes, and uploads them to Supabase Storage. This is independent of the other two entry points — it's the upstream counterpart that produces the folders `run_webhook.py`'s `/webhook` expects, but nothing in this repo automatically calls `/webhook` once an upload finishes. Some other, unspecified process is expected to do that.

Needs: `SUPABASE_URL`/`SUPABASE_KEY`/`SUPABASE_BUCKET`. No Postgres vars — this path never writes to the database.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `FileNotFoundError` naming a `.onnx` file under `models/` | Missing exported model | Run `python tools/export_to_onnx.py --all` (see [`07`](07-testing-and-dev-tools.md)) after placing the source `.pt` weights |
| `psycopg2.connect()` fails immediately | A required `POSTGRES_*` var is unset | Check all 5 required vars are in your `.env` |
| Pipeline runs but nothing uploads/downloads via Supabase | `SUPABASE_URL`/`KEY` unset | Expected for `run_local.py` (tolerated); required for `run_webhook.py`/`run_live_capture.py` |
| `pip install -r requirements.txt` fails on a `torch==...+cu118` line | You're looking at `requirements-export.txt` (or an older/wrong file) | The runtime `requirements.txt` on this branch has no torch line at all — see the table above |
